# Конфиг ядра: единственный источник — `t1100.fragment`, `t1100_defconfig` генерируется

**Статус:** accepted (18.11.2026)

Правки конфига ядра вносятся только в `configs/t1100.fragment`; `configs/t1100_defconfig`
— это `make savedefconfig` из результата «arm64 defconfig + фрагмент», его руками
не правят. Инвариант проверяемый: `cp configs/t1100_defconfig <out>/.config &&
make olddefconfig` даёт **побайтово тот же** `.config`, что и сборка из фрагмента.

## Почему это записано

18.11 при добавлении `CONFIG_SQUASHFS_{XZ,LZ4,LZO,ZSTD}` выяснилось, что
снимок `t1100_defconfig` отстал от фрагмента на 199 строк: в нём не было
`CONFIG_MT6370` (зарядка), панели IT6112, `STK3310`, USB-Wi-Fi-адаптеров,
`# CONFIG_CPUFREQ_DT is not set` и т. д. Сборка из фрагмента и сборка из
снимка давали разные ядра — при этом именно снимок считался «конфигом
прошивки». Снимок перегенерирован, инвариант восстановлен (`diff` пуст).

## Последствия

- Любая правка фрагмента обязана сопровождаться регенерацией снимка, иначе
  следующая сборка «из снимка» потеряет настройку. Проверка — командой выше.
- `scripts/build-kernel-remote.sh --config` мержит фрагмент; regen снимка:
  `make -C src O=out ARCH=arm64 savedefconfig` на build-хосте.
