# Аппаратный декод видео: отложен, пока не доказан SCP-путь

**Статус:** superseded by ADR 0004 (20.11.2026)

> **Обновлено 20.11.2026:** SCP-путь доказан — mainline `mtk_scp` поднимает
> MT8183-прошивку на MT6771, `mtk-vcodec-dec` пробуется. См.
> `docs/scp-bringup.md`, `docs/vcodec-bringup.md` и ADR 0004.

Узел `vcodec_dec` в `mt6771.dtsi` остаётся удалённым: mainline-драйвер
`mediatek,mt8183-vcodec-dec` требует rproc (`mediatek,scp`/`mediatek,vpu`) с
сервисом `AP_IPIMSG_DEC_*`, а в стоковой SCP-прошивке MT6771 (`scp_a`, p21)
строк `vdec`/`codec`/`h264`/`hevc`/`vp9` **нет вовсе**. Сам SCP-блок при этом
совпадает с MT8183 (адрес `0x10500000`, IRQ 174, `tinysys` + IPI v02), а
регистры VDEC совпадают с MT8183 (`0x16020000…`, IRQ 250) — то есть железо
похоже, а сервисного слоя нет.

**Решение:** пользовательский путь — софт-декод (VP9/AV1 на CPU: 4K60 ≈ 170 %
CPU, 1080p комфортно). Параллельно — короткий спайк «порт `mtk_scp` под
MT6771, критерий успеха — прошивка стартует и отвечает на IPI». Свой
VDEC-драйвер по вендорному VAL — только если найдётся вендорный исходник
(публичное дерево 4.4.146 его не содержит: в `videocodec/mt6771/` нет ни
`request_firmware`, ни работы с SCP/VPU).

## Рассмотренные варианты

| Вариант | Почему нет (пока) |
|---|---|
| Включить `mediatek,mt8183-vcodec-dec` как есть | нужен IPI-сервис vdec в SCP-прошивке; в стоковой `scp_a` его нет |
| Свой VDEC-драйвер (порт вендорного VAL) | нет TRM и нет вендорного исходника слоя HW; недели работы с высоким риском |
| GPU-декод (panfrost) | Mali-G72 не содержит видеоблока, Vulkan Video на panfrost отсутствует |
| Софт-декод | это и есть текущее решение; 1080p идёт, 4K дорого |

## Последствия

- `docs/vdec-plan.md` — карта фактов и пошаговый спайк (DT `scp@10500000` +
  `mediatek,mt6771-scp` на `mt8183_of_data`, регион `scp_mem_reserved`, проверка
  IPI).
- Порт SCP ценен и сам по себе (вендорная схема: сенсоры/аудио/камера через SCP),
  поэтому спайк не выбрасывается, даже если декод не поедет.
- Браузер останется на софт-декоде при любом исходе: Firefox умеет только
  VA-API, `v4l2m2m` ему не подходит.
