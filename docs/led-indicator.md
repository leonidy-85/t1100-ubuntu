# Индикаторный светодиод (MT6370)

Светодиод у камеры — красный канал RGB-подсветки PMIC **MT6370**. Ядро им не
управляет: `CONFIG_LEDS_MT6370_RGB` выключен, узлов LED в DTS платы нет, а
`/sys/class/leds/` пуст. Поэтому индикатором занимается userspace-демон
`t1100-led`, который пишет в PMIC по I2C.

## Железо и доступ

| | |
|---|---|
| шина | `/dev/i2c-5` |
| адрес | `0x34` (устройство `mt6370`, регмап `5-0034`) |
| каналы | ISINK1 = красный, ISINK2 = зелёный, ISINK3 = синий, ISINK4 = CHRIND (индикатор заряда) |
| проверка | `/sys/kernel/debug/regmap/5-0034/registers` |

**Важно:** чип отвечает на **8-битную адресацию регистров**. Регистр `0x185`
из даташита/драйвера на проводе — это `0x85`. 16-битная big-endian адресация
(`struct.pack(">H", reg)`) не работает: чтения возвращают 0, записи
игнорируются. Адрес устройства занят драйвером, поэтому нужен
`ioctl(fd, I2C_SLAVE_FORCE, 0x34)`, иначе `ENXIO`/`EBUSY`.

## Регистры (16-битные адреса, в проводе — младший байт)

| адрес | смысл |
|---|---|
| `0x182/0x183/0x184` | RGB1/2/3 DIM: биты 6..5 — режим, 4..0 — duty |
| `0x185` | RGB_EN: биты 0..3 — включение ISINK4..ISINK1 (`BIT(4-id)`), **бит 7 обязателен** для выхода тока, биты 4..7 — `F_RGB_EN` |
| `0x186/0x187/0x188` | ISINK1/2/3: биты 2..0 — ток, 5..3 — частота |
| `0x189` | RGB1_TR |
| `0x192` | CHRIND_DIM: бит 7 — `CHGIND_EN`, биты 6..5 — режим, 4..0 — duty |
| `0x193` | CHRIND_CTRL: биты 1..0 — ток (0..3), 4..2 — частота |
| `0x194` | CHRIND_TR |
| `0x17E` | FLEDEN (вспышка): бит 3 — torch, бит 2 — strobe |
| `0x175` | FLEDITOR1 — ток вспышки |

Режимы: `0` — PWM, `1` — breathing, `2` — постоянный ток (cc_mode).
Рабочая комбинация для ровного красного: `0x86=0x03`, `0x82=0x5f`
(режим 2 + duty 31), `0x85=0x88` (бит 7 + ISINK1), плюс синхронно
`0x93=0x03`, `0x92=0xdf` для CHRIND.

После загрузки ядро/загрузчик оставляет `0x185=0x88`, `0x192=0xdf`,
`0x193=0x03` — поэтому диод горит красным постоянно, пока его не погасить.

## Демон

`rootfs-overlay/usr/local/sbin/t1100-led` + юнит
`rootfs-overlay/usr/lib/systemd/system/t1100-led.service`
(`WantedBy=multi-user.target`, `Restart=always`).

Поведение:

- на зарядке (`/sys/class/power_supply/mt6370-charger/online` = 1) — ровный свет;
- уведомление — мигание (400 мс, по умолчанию 6 с);
- иначе — всё выключено.

Каналы и параметры задаются в `/etc/t1100-led.conf`:

```ini
charge_channel=1     # 1=красный, 2=зелёный, 3=синий, 4=CHRIND
notify_channel=1
charge_dim=0x60
notify_dim=0xff
blink_ms=400
notify_seconds=6
watch_dbus=1
```

Ручное управление и диагностика:

```sh
t1100-led notify 10   # мигать 10 секунд
t1100-led off         # погасить
t1100-led status      # состояние зарядки и снимок регистров
```

Сокет `/run/t1100-led.sock` принимает те же команды.

## Уведомления Phosh

Демон слушает `org.freedesktop.Notifications.Notify` на сессионной шине
пользователя. Root к сессионной шине не допускается, поэтому watcher
запускается через `su -s /bin/sh <user> -c` с
`DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/<uid>/bus`.

В правиле `dbus-monitor` кавычки должны быть **одинарными** внутри
аргумента, иначе шина отвечает `MatchRuleInvalid`:

```sh
dbus-monitor --session "type='method_call',interface='org.freedesktop.Notifications',member='Notify'"
```

## Известные ограничения

- Драйвер зарядника может перезаписывать регистры CHRIND при событиях
  зарядки; демон переприменяет своё состояние раз в секунду.
- Яркость задаётся duty (0..31) и током (0..3), плавной регулировки нет.
- Зелёный/синий каналы на этой плате не видны (физически один красный
  светодиод), поэтому уведомления мигают тем же красным.
