# USB host (OTG) на T1100

Порт USB-C на MT6771 — это dual-role контроллер `mtu3` (`11201000.usb`) с
xHCI-блоком (`11200000.usb`) и Type-C-логикой на MT6370. Аппаратно он умеет
и устройство, и хост; OTG-питание 5 В даёт boost внутри MT6370
(`mt6370-usb-otg-vbus`).

## Что включено по умолчанию и почему

Порт по умолчанию в режиме **peripheral** (`role-switch-default-mode =
"peripheral"` в DTS). Это сделано осознанно: в этом режиме работает RNDIS
(`usb0`, 10.42.66.66) — сетевой канал для SSH, и tcpm намеренно не управляет
role switch, чтобы смена power-role при подключении зарядника не рвала его.

## Как переключить

```sh
t1100-usb-host on       # host: OTG 5 В на VBUS, можно подключить флешку/клавиатуру
t1100-usb-host off      # обратно в peripheral (RNDIS)
t1100-usb-host status   # роль, зарядка, список USB-устройств
```

Скрипт пишет в `/sys/class/usb_role/11201000.usb-role-switch/role`
(`host` / `device`). В host-режиме он отказывается работать, если подключён
зарядник: VBUS в этот момент уже занят, и совмещать зарядку с OTG нельзя.

## Что проверено на железе

- `echo host` → роль `host`, регулятор `mt6370-usb-otg-vbus` включается,
  на VBUS 5.05 В;
- `echo device` → роль `device`, VBUS выключается, gadget снова поднимает
  pull-up, `usb0` (10.42.66.66) на месте;
- переключение туда-обратно не ломает Wi-Fi и не требует перезагрузки.

## Ограничения

- Только USB 2.0 High-Speed: в DTS стоит `mediatek,u3p-dis-msk = <1>`, SuperSpeed
  на этом SoC/плате не разведён.
- Пока порт в host, заряжаться через него нельзя (VBUS — выход, а не вход), и
  RNDIS-канал `usb0` пропадает; SSH остаётся по Wi-Fi.
- Реальную энумерацию устройства (флешка, клавиатура) ещё предстоит проверить
  с OTG-переходником USB-C → USB-A: без физического девайса виден только
  корневой hub.
- Автоматический переход по `data_role` от tcpm возможен, но рискован: любое
  изменение power-role будет дёргать mtu3 и может убить RNDIS. Поэтому роль
  переключается вручную.
